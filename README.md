# 声呐战辅助器

一个在浏览器本地运行的独立分析工具。用户手动创建地图并记录探测结果，工具不会读取游戏内存、自动点击或控制游戏，也不需要后端、数据库和登录功能。

## 当前功能

- 创建最大 10×10 的矩形地图
- 使用长度 2～5 的潜艇数量配置舰队
- 支持“仅上下左右”和“包含对角”两种潜艇间隔规则
- 为同一长度潜艇生成并复用全部水平、垂直单艇候选位置
- 计算候选的占用格、禁止邻接区域和候选间冲突
- 将未知格子标记为未命中或命中，并按完整位置记录已击沉潜艇
- 撤销上一步、重置当前地图并显示操作历史
- 在 Web Worker 中自动分析并显示每格潜艇占用概率
- 按当前精确或近似概率推荐占用概率最高的可攻击未知格
- 自动保存并恢复当前浏览器中的正式对局证据
- 使用固定滚动容器承载地图，适配 Windows 浏览器和 iPad Safari

## 舰队规则

- 潜艇是长度 2～5 的连续直线
- 只能水平或垂直放置
- 潜艇不能重叠
- 潜艇之间必须按照所选邻接规则间隔至少一格
- 默认规则为 `orthogonal-and-diagonal`，即同时禁止上下左右和对角邻接
- `orthogonal-only` 只禁止上下左右邻接

真实游戏海域配置尚未确认，因此正式界面目前只提供“自定义配置”。代码保留了 `SeaPreset` 和预设选择器扩展结构，但没有将人为构造的配置伪装成真实海域。

界面中的初始数值也只是自定义填写示例，不代表游戏官方默认配置。使用前请确认实际地图、舰队数量和潜艇邻接规则。

## 当前限制

对局状态将未命中、命中与完整的已击沉潜艇分开记录。已击沉潜艇必须录入长度、方向和起点，格子不再具有可独立编辑的击沉状态；剩余舰队按潜艇长度扣减。

当前概率引擎会精确枚举受搜索限制约束的完整舰队布局并生成概率矩阵。页面会显示概率数字，并从可攻击的未知格中稳定选择概率最高者；精确推荐与采样近似推荐会明确区分。尚未实现概率热力图、信息增益推荐或多步攻击规划。

概率引擎支持把已确定长度、方向和起点的潜艇作为固定证据。引擎会从规则候选中重新生成其占用格和禁止区域，不接受调用方提交派生位掩码。固定潜艇会从待搜索舰队中扣除，但最终概率仍表示原始完整舰队。

## 可选合成性能测试

性能测试默认跳过，不代表真实游戏海域。在 PowerShell 中可执行：

```powershell
$env:RUN_LAYOUT_PERFORMANCE='1'
npm run test -- src/engine/layoutAnalysis.performance.test.ts
```

测试只检查搜索限制、稳定运行和结果状态，不使用固定毫秒阈值。

采样引擎使用顺序重要性采样，默认参数为：

- `seed`: `0x5eed1234`（十进制 1,592,594,996）
- `targetAcceptedSamples`: `10,000`
- `maxAttempts`: `100,000`

成功结果使用 `status: 'estimated'`，明确表示概率不是精确枚举结果。采样会在达到目标接受样本数或达到最大尝试次数时停止：

- `targetReached` 严格表示 `acceptedSamples >= targetAcceptedSamples`。
- `no-samples` 表示有限尝试中没有成功样本，不能证明不存在合法布局。
- `effectiveSampleSize`（ESS）反映加权样本的有效数量，不是置信区间。
- `maxWeightFraction` 是最大单一样本权重占总权重的比例；越接近 1，权重退化越严重。`no-samples` 时为 `null`。

采样合成性能测试使用独立变量：

```powershell
$env:RUN_LAYOUT_SAMPLING_PERFORMANCE='1'
npm run test -- src/engine/layoutSampling.performance.test.ts
```

## v0.6 统一分析编排器

纯 TypeScript API `analyzeBoard` 支持三种模式：

- `exact`：只运行精确枚举。默认 `maxVisitedNodes: 1_000_000`、`maxLayouts: 100_000`。
- `estimated`：只运行顺序重要性采样。默认 `seed: 0x5eed1234`、`targetAcceptedSamples: 10_000`、`maxAttempts: 100_000`。
- `auto`（默认）：始终先运行精确枚举；其精确阶段默认 `maxVisitedNodes: 100_000`、`maxLayouts: 25_000`，仅在达到限制后回退到采样。

统一结果严格区分：`exact` 是精确概率；`proven-no-layouts` 是唯一严格证明无合法布局的状态；`estimated` 始终是近似估计；`exact-limit-reached` 表示仅精确模式达到限制；`unavailable` 表示采样未获得成功样本，不能解释为无解。精确限制原因通过 `exactLimitReason` 区分 `max-visited-nodes` 与 `max-layouts`。回退结果只保留 `exactVisitedNodes` 和停止前已发现的 `exactPartialLayouts`，不会公开或混合精确阶段的部分概率矩阵。

子选项按模式验证：`exact` 只验证精确选项，`estimated` 只验证采样选项；`auto` 在开始搜索前同时验证两者。结果不包含运行耗时，保证相同输入和 seed 可复现。

## v0.7 Web Worker 执行层

`AnalysisWorkerClient` 通过 Vite 模块 Worker 在后台调用现有 `analyzeBoard`，不复制规则、精确搜索或采样算法。Worker 消息只包含可结构化克隆的普通对象和数组，协议禁止 `bigint`、循环引用和畸形的统一分析结果。

同一客户端只允许一个活动请求。新请求会以 `superseded` 原因取消旧请求；显式 `cancel()` 使用 `cancelled` 原因。由于同步引擎无法合作式中断，取消采用 terminate + recreate，不返回部分结果。`dispose()` 会永久关闭客户端；普通创建或重建失败则是可恢复状态，后续 `analyze()` 会再次尝试创建 Worker。

Worker 的 `error`、`messageerror`、畸形响应和 `postMessage` 异常都会触发硬重置：清空 pending、移除监听器、终止旧 Worker、增加 generation 并尝试创建新 Worker。领域错误通过序列化保留稳定 `LayoutAnalysisError.code`，正式协议不发送错误堆栈。

生产构建使用独立的 `analysisWorkerBuildEntry.ts` 进入 Vite 模块图，不修改或接入 `App.tsx`、`main.tsx`，也不会在正常页面启动时自动创建 Worker。

## v0.8 对局证据模型

普通格子只记录未知、未命中或命中。完整已击沉潜艇通过规则模块生成的稳定 Placement ID 保存，并在确认时检查边界、舰队数量、重复、未命中冲突、命中禁止邻接冲突以及潜艇间的重叠和邻接规则。固定潜艇范围内的原始命中会保留，但转换为 `BoardEvidence` 时不会重复进入 `occupied`。

重置会清空格子观察、固定潜艇和可见历史；重置后立即撤销可以恢复完整快照。固定潜艇录入中的长度、方向和预览操作不会使该快照失效，正式标记、添加或删除则会使旧重置快照失效。

## v0.9 页面异步分析

页面通过 `AnalysisWorkerClient` 以固定 `auto` 模式运行统一分析。正式地图、格子观察或固定潜艇发生变化后会防抖约 200ms；手动“重新计算”会跳过防抖，“取消分析”会终止当前 Worker 计算。录入模式、长度、方向和预览等临时状态不会触发分析。

页面严格区分精确结果、近似估计、严格无布局、精确超限、采样不可用和执行错误。只有精确或近似结果会向棋盘提供概率矩阵；新输入、计算中、取消或失败时会立即移除旧概率。棋盘仅显示数字百分比，不使用颜色热力图。

## v0.10 概率攻击推荐

推荐器只考虑尚未攻击且不属于固定潜艇的未知格，并以概率矩阵中的真实全局最大值为基准，通过 `1e-12` 容差统计并列最高候选。并列时按行列顺序选择第一个，不使用随机数。矩阵尺寸、全部概率值和固定潜艇证据会在推荐前验证；普通无目标返回空结果，非法输入则返回稳定领域错误。

固定潜艇录入模式只隐藏推荐卡片和棋盘高亮，不取消分析或发起额外 Worker 请求。退出录入后，只要正式证据未变化，推荐会直接恢复。

## v1.0 个人使用版

当前地图配置、格子观察和完整已击沉潜艇会在正式变化后约 300ms 自动保存到当前浏览器的 `localStorage`，刷新页面后自动恢复并重新分析。概率、推荐、Worker 状态、录入预览、操作历史和撤销快照不会写入存档；恢复后历史为空，撤销从恢复后的新操作开始。

存档使用版本化的 `SavedGameV1` 结构和固定键 `sonar-helper.saved-game`。读取时会重新生成 Board 坐标，逐项验证配置、观察矩阵和固定潜艇规则。损坏的 v1 存档会被忽略并尝试移除；未知版本不会加载，也不会自动删除。

“结束并清除对局”会同时结束当前对局、取消分析并清除本地存档。浏览器禁用存储、Safari 隐私限制或存储操作失败时，当前页面仍可继续使用，但刷新后可能无法恢复。

